# NYC Rent Burden Atlas

An interactive research dashboard on renter cost burden and affordable housing production across New York City's five boroughs.
It is built from Levi Lebel's Statistics coursework: Homework 4, *Rent Burden in New York City*, with HW3 used as a cross-check.

The site is fully static (HTML, CSS, vanilla JS and D3 from a CDN), so it can be hosted on GitHub Pages from `docs/` with no build step.

## Structure

```
nyc-rent-burden/
├── docs/                      ← website root (GitHub Pages "docs/" folder)
│   ├── index.html
│   ├── assets/css/styles.css
│   ├── assets/js/
│   │   ├── app.js             ← loads data, initialises sections, shared state
│   │   ├── util.js            ← METRICS registry (labels/units/sources), formatting, tooltip
│   │   ├── charts.js          ← reusable D3 components (bars, stacks, strip, scatter, columns)
│   │   └── sections/*.js      ← one module per page section
│   ├── content/research.json  ← sources + research-log modules (edit when adding assignments)
│   └── data/                  ← GENERATED by the pipeline — do not edit by hand
├── pipeline/
│   ├── build_data.R           ← reproduces HW4 from raw files, validates, writes docs/data/
│   ├── verify_outputs.R       ← independent base-R recheck of every published number (run after each build)
│   ├── review_zip_inclusion.R ← read-only impact study: ZCTAs 10162 / 10279
│   ├── review_pressure_index.R← read-only diagnostics + sensitivity of the HW4 pressure index
│   ├── config.example.R       ← template for machine-specific paths
│   └── config.local.R         ← (git-ignored) RESEARCH_ROOT on this machine
├── validation/                ← validation_report.md + CSV extracts (regenerated each build)
├── tools/serve.ps1            ← local static server (PowerShell; no Node/Python needed)
└── CHANGELOG.md
```

The original research files are **read-only inputs**. The pipeline never writes to them.

## Rebuild the data

```bash
Rscript pipeline/build_data.R
```

Then `Rscript pipeline/verify_outputs.R`, which exits non-zero if any published value disagrees with the raw files. Each check is labelled:
**RECOMPUTE** (independent recalculation from raw files), **REFERENCE** (vs. HW4 figure values / HW3 file), **CONSISTENCY** (internal), or **INFO** (descriptive, never counted as a pass).
After any change to the build, also rerun `review_zip_inclusion.R` and `review_pressure_index.R` so the reports in `validation/` stay current.

### Baseline vs. additions
The HW4 baseline lives in `borough_summary.json`, `statistics.json`, `hpd_by_year.json` and the original fields of `zip_data.json`. Website-only analyses are kept separate so the baseline stays traceable:
`alternative_ranking.json` and the `*_alt` fields of `zip_data.json` hold the exploratory ranking, and `excluded_zctas.json` holds the 10162/10279 comparison. Never change an HW4 field to implement a variant; add a new field or file instead.

## External dependencies
- **D3 7.9.0** from `cdn.jsdelivr.net`, with `unpkg.com` as an automatic fallback (`index.html`). `assets/js/boot.js` shows a clear message if neither loads. The text content stays readable, but charts and the theme toggle won't work.
- **Google Fonts** (Inter, Source Serif 4), with system fonts as the fallback.
- No other runtime services; all data are static files in `docs/data/`.
Requires R ≥ 4.3 with `tidyverse`, `jsonlite` and `sf`.

## Themes

Light and dark themes share one set of components. CSS colours are tokens in `styles.css` (`:root` and `:root[data-theme="dark"]`). Chart mark colours are in `THEMES` in `util.js`. Charts must take colours from `COLORS` / `seq()` at draw time and register with `onResize` (or `onTheme` for legends), so a theme switch can redraw them. ZCTA boundaries come from the local `tigris` cache (`cb_2020_us_zcta520_500k`).

## Preview locally

```bash
powershell -ExecutionPolicy Bypass -File tools/serve.ps1 -Port 8765
```

Then open http://localhost:8765/. Opening `index.html` directly from disk will not work, because browsers block `fetch()` on `file://`.

## Adding a new assignment (e.g. Homework 5)

1. **Inspect** the new assignment folder: code, raw data, outputs.
2. **Extend the pipeline** with a new clearly delimited section, or a new script `pipeline/build_hw5.R`. It should read raw files from their original location, reproduce the assignment's calculations, add checks with `add_check()`, and write to new files in `docs/data/` (e.g. `hw5_*.json`). Do not overwrite existing outputs.
3. **Register** the data source(s) and a new module entry in `docs/content/research.json`. Set `status`, `scope`, `notes` and an `integration` note explaining how it is used.
4. **Add UI**: new metrics go in `METRICS` (`util.js`), and a new section goes in `docs/assets/js/sections/<name>.js` with markup in `index.html` and an entry in `SECTIONS` (`app.js`).
5. **Record** the change in `CHANGELOG.md`.

Only datasets that are actually comparable should be merged. For example, a different ACS vintage or geography needs its own section rather than being mixed into the 2024 ZCTA tables.

## Publishing

- **Live site:** https://levilebel.github.io/nyc-rent-burden-atlas/
- **Repository:** https://github.com/levilebel/nyc-rent-burden-atlas (GitHub Pages: branch `main`, folder `/docs`)

Every push to `main` redeploys the site automatically, usually within a minute.
Raw ACS/HPD downloads, `.Rproj` files, assignment documents and `pipeline/config.local.R` are **not** in the repository (see `.gitignore`).

### Update workflow
1. Add or change the analysis (see "Adding a new assignment" above).
2. `Rscript pipeline/build_data.R`, then `Rscript pipeline/verify_outputs.R` (must report 0 FAIL).
3. Preview locally (`tools/serve.ps1`) and check both themes.
4. Record the change in `CHANGELOG.md`.
5. Commit and `git push`. The Pages deployment then runs on its own.
